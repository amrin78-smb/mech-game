# Build log

One entry per APK built. Each records the Unity version, what was in it, how it was signed,
its size and SHA-256, and — separately — what was actually tested on a phone and what was
not. "Built" and "works on the phone" are kept apart on purpose: only the owner's playtest
can move something into the second column.

  uploaded fully, leaving a draft that `gh`'s own cleanup then failed to remove. The release

  The script now passes an absolute path.

Notes:

- **The APK grew from 76 MB to 98 MB.** It is almost entirely `libil2cpp.so`: 72.6 MB for
  arm64 and 58.6 MB for armv7 uncompressed, against 235 MB of uncompressed content in all.
  This is a Development build, so the profiler and debug symbols are in it, which is what a
  playtest on the Redmi wants. `AndroidBuild.Release()` exists for anything handed further
  on, and Phase 5's performance pass is where size gets looked at properly.
- A first 0.2.0 build came out at 82 MB after an earlier build of the same version had been
  interrupted, which suggests it reused part of that run's IL2CPP output. It was discarded
  and rebuilt from scratch rather than published. Do not publish an APK from a build that
  followed an interrupted one without rebuilding.
- `scripts/release-apk.sh` used `gh release view --json databaseId`, which this `gh` does not
  have, and a draft release cannot be fetched by tag through the REST API either. It now
  finds the release id from the list. The release itself was unaffected: the asset had
  uploaded and only the publish step needed finishing.
